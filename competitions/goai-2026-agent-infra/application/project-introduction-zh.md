# 初赛作品简介

## 项目名称

**TITMAS 智能体可信发布闸门**

英文名称：TITMAS Verified Agent Release Gate（TITMAS 智能体可信发布闸门）

## 500字以内正式版本

TITMAS 智能体可信发布闸门面向企业软件研发场景，解决 AI 编程智能体生成或修改代码后“能否合并、发布、回滚和复核”的工程化问题。系统以 AgentTeams（智能体团队框架）为协同设计基点，组织仓库接入、测试与攻击、证据验证、发布闸门四类智能体，将 Issue（议题）、Pull Request（拉取请求）、测试结果、工具调用、授权边界和运行记录整理为可移交、可离线复验的 Evidence Bundle（证据包）与 Receipt（回执）。系统不把日志等同于证据，也不把验证等同于授权；它输出 PASS（通过）、FAIL（失败）、INCOMPLETE（证据不完整）或 HUMAN_REVIEW（人工复核），并在高风险变更中触发人工审批、失败关闭和回滚建议。现有基础包括 TITMAS 数字单元公开参考演示、证据打包与验证能力、Python（Python 编程语言）/ TypeScript（TypeScript 编程语言）软件开发工具包和 MCP（模型上下文协议）适配器候选。项目计划开放 GitHub Action（GitHub 自动化动作）、命令行工具、Agent Identity（智能体身份）清单、Skill（技能）契约、样例证据包和部署文档，使其他团队可复用到研发、运维和安全审计流程。

## 字段拆解

### 问题与场景

编程智能体可以快速修改代码，但企业缺少一个独立、确定、可审计的发布前检查层，无法统一判断任务来源、权限、测试、工具调用和证据完整性。

### 核心解决方案

由多个窄职责智能体完成变更接入、测试攻击、证据验证和发布决策；AgentTeams（智能体团队框架）负责编排，TITMAS 证据层负责可移交证据，发布闸门执行失败关闭。

### 创新点与差异化

1. 把协作执行与独立验证分离，避免同一个智能体既执行又自证；
2. 保留 `PASS`（通过）、`FAIL`（失败）、`INCOMPLETE`（证据不完整）和 `HUMAN_REVIEW`（人工复核），不把未知状态强行判定为通过；
3. 将 Trace（轨迹）、Log（日志）和测试结果转换为可离线复验的证据包，而不是只依赖在线观测页面；
4. 将人工审批、回滚和审计作为主流程，不作为事后补丁。

### 开放与复用价值

公开安全部分将提供 Agent Identity（智能体身份）模板、Skill（技能）契约、证据结构、GitHub Action（GitHub 自动化动作）候选、命令行验证器、样例输入输出和测试方法。相同模式可迁移到运维变更、安全处置、数据管道和模型发布流程。

### 当前进展

已具备身份、边界、证据和健康状态的确定性参考演示；已具备软件开发工具包和 MCP（模型上下文协议）适配器候选；正在完成 AgentTeams（智能体团队框架）映射、发布闸门场景和初赛方案材料。当前不声明生产就绪、正式认证或外部标准采纳。
