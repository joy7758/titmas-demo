# Agent Identity（智能体身份）与 Skill（技能）清单

## 设计原则

每个智能体只承担窄职责，权限与工具按最小必要范围授予。Manager Agent（管理智能体）负责编排，不直接替代验证器或审批者；Worker Agent（执行智能体）通过结构化交接对象传递上下文和结果。

## 核心 Skill（技能）清单

### 1. Repository Context Intake Skill（仓库上下文接入技能）

- 用途：把仓库、议题、拉取请求、提交、作者和任务说明规范化为一个变更上下文对象。
- 输入：仓库地址、引用、提交标识、任务标识、只读凭证引用。
- 输出：`change-context.json`（变更上下文文件）及内容摘要。
- 调用条件：收到新的变更验证任务。
- 依赖工具：GitHub API（GitHub 应用程序接口）或等价代码托管接口。
- 失败处理：引用不存在、权限不足或上下文不完整时返回 `INCOMPLETE`（证据不完整）。
- 安全边界：默认只读；不接收明文令牌；不修改分支。
- 复用价值：可迁移到代码审查、依赖升级、模型发布和配置变更。

### 2. Test Evidence Capture Skill（测试证据采集技能）

- 用途：执行受控测试并保存命令、环境、退出码、报告摘要和产物哈希。
- 输入：变更上下文、测试配置、资源限制。
- 输出：测试事件、报告、日志引用、失败原因码。
- 调用条件：上下文接入通过且测试配置可解析。
- 依赖工具：持续集成系统、测试框架、静态分析器、依赖扫描器。
- 失败处理：超时、资源不足、测试崩溃均显式失败，不自动重试非幂等操作。
- 安全边界：在隔离环境运行；禁止访问生产密钥和生产写接口。
- 复用价值：可供测试、证据和发布决策智能体重复使用。

### 3. Evidence Bundle Verification Skill（证据包验证技能）

- 用途：将执行事件、策略、来源和产物整理成可移交证据包，并离线检查结构和完整性。
- 输入：上下文、测试报告、策略引用、事件序列。
- 输出：Evidence Bundle（证据包）、Receipt（回执）、原因码和验证摘要。
- 调用条件：存在最小必需证据集合。
- 依赖工具：TITMAS 证据验证器、哈希函数、可选签名组件。
- 失败处理：缺字段返回 `INCOMPLETE`（证据不完整）；签名或哈希异常返回 `FAIL`（失败）。
- 安全边界：验证不授予发布权限；不修改原始证据。
- 复用价值：可用于软件发布、运维变更、安全事件和数据处理任务。

### 4. Policy Boundary Check Skill（策略边界检查技能）

- 用途：检查任务、工具、权限、风险等级和审批要求是否符合声明策略。
- 输入：变更上下文、工具调用记录、策略版本、风险标签。
- 输出：策略符合状态、原因码、需要的审批级别。
- 调用条件：证据包结构可解析。
- 依赖工具：策略文件、规则验证器。
- 失败处理：未知策略版本或冲突规则返回 `HUMAN_REVIEW`（人工复核）。
- 安全边界：策略结果不证明事实真伪，只判断声明条件是否满足。
- 复用价值：可用于权限审批、变更管理和合规检查。

### 5. Release Gate Decision Skill（发布闸门决策技能）

- 用途：把验证结果、策略状态和人工审批状态转换为确定性发布决定。
- 输入：验证回执、策略结果、风险等级、审批记录。
- 输出：`PASS`（通过）、`FAIL`（失败）、`INCOMPLETE`（证据不完整）或 `HUMAN_REVIEW`（人工复核）。
- 调用条件：已完成最小验证流程。
- 依赖工具：规则引擎、GitHub Check（GitHub 检查）或持续集成状态接口。
- 失败处理：任何未知关键状态默认失败关闭。
- 安全边界：不直接部署；高风险操作必须由人类批准。
- 复用价值：可嵌入 GitHub Action（GitHub 自动化动作）、持续集成流水线或发布平台。

### 6. Human Approval and Rollback Skill（人工审批与回滚技能）

- 用途：生成审批包、记录审批决定、输出回滚步骤并验证回滚结果。
- 输入：风险摘要、证据引用、候选动作、回滚计划。
- 输出：审批记录、回滚命令计划、回滚验证结果。
- 调用条件：高风险变更、策略冲突、证据不完整或人工主动介入。
- 依赖工具：AgentTeams（智能体团队框架）可见协作通道、代码托管审批接口。
- 失败处理：审批超时保持阻断状态；回滚失败升级事件。
- 安全边界：不允许静默批准；审批者身份和时间戳必须留痕。
- 复用价值：可迁移到运维、安全处置和数据治理流程。
